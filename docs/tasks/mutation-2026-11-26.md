# Mutation testing of the cabinet, the commitments and the geographic layer

Asked for by F15 of `todo.md`. Run on 2026-11-26 over the code with tasks 19 to 21 and the fixes
of section 2 built, with `tests/run_mutmut.py` (decorated functions included) limited to
`gobernar360.platform.geo.*`, `gobernar360.dashboards.cabinet.*` and
`gobernar360.platform.commitment*`, leaving `tests/test_seed.py` and `tests/test_architecture.py`
out (they are slow and would only hide what the other tests miss).

The database was PostgreSQL 16 with a stand-in for the PostGIS extension (see the report of the
session), not `postgis/postgis:16-3.4`.

**5460 mutants, 5255 killed (96.2 %); the target is 80 %.** By part: cabinet 96.6 %, commitments 96.1 %, geographic layer 96.0 %.

After that run, tests were added for the survivors that were real gaps in the new code: which zone
the import takes for the radius, what IDECOR is asked for, what it counts, and who is told when an
owner leaves. They were not measured again. What is left is mostly of four kinds: join conditions
SQLAlchemy infers, last-resort orderings (`..., id`), `zip(strict=...)`, and row locks
(`for_update`), which only show with two requests at once.
